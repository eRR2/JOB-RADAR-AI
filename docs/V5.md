# V5 AI career research preview

Branch: `feat/v5-ai-career-research`. No main merge, stable Release or second-PC update.

## Why discovery changed

The previous search divided three queries/five details/eight requests between markets,
selected a few ATS boards before web research, and latched LinkedIn failures permanently.
These transport choices limited exploration independently of career relevance.

V5 uses `ResearchHunter`, with native Codex public web research as the discovery path.
AI chooses role families, priority employers when requested, adjacent industries and further
avenues. Indexed LinkedIn vacancy links are the first focus; useful employer publications
remain equally eligible. No ATS adapter is required to retain a web-observed vacancy.

Research proceeds in rotating market batches, without dividing a tiny request quota.
Twenty records is the structured response envelope per batch, not a total job ceiling.
Runs have a fifteen-minute time window, cancelable CLI calls of at most four minutes,
bounded output/HTTPS responses, robots and publisher restrictions. Subscription failures
stop rather than trigger billing fallback. Remaining avenues/results are retained.
The separate description recovery operation also uses a time window in V5, rather than
the legacy ten-job/five-description quota. These controls do not imply unlimited access.

## Evidence and privacy

An offline AI step prepares an anonymous professional brief. Raw CV, original user text
and source quotes do not enter the web-enabled discovery call. That call receives the
brief, reviewed structured direction/geography, scoped learning and existing public job
observations. Anonymization is model-mediated; it is not a mathematical anonymity guarantee.
Private interpretation/evaluation still sends approved career context to the selected provider.

Codex `--json` completed `web_search` events supply actual URL/title/snippet observations.
Model-written evidence is separate: unobserved URLs are refused and unsupported source
fields remain unknown. A city or the query's market cannot establish a vacancy country.
Indexed text is never a full description or proof of current availability. Preliminary
career perspective stays separate from a full ATS/HR evaluation and cannot create a
Recommended entry. Real controlled retrieval plus exact employer/title/locality/country
and requisition checks establishes full-description evidence. Original LinkedIn identity
and URL survive independently published descriptions. Ambiguous associations are refused.

Direct LinkedIn is an optional, separately consented description transport. It is not used
by the web discovery capability tests. HTTP 429 respects delta-seconds or HTTP-date
Retry-After; without a valid header it uses 1h, 2h, 4h ... up to 24h backoff.
Completed responses clear pending markers, including errors. Interrupted requests get
an explicit unknown-extent cooldown. The same transport instance never retries after
denial. Expired 429 cooldown allows a subsequent user/scheduled run to check normally.
403/auth/challenge restrictions remain authoritative until resolved; there is no clear-stop
button or proxy/auth/endpoint bypass. Public controlled publishers use the same 429 policy.
Reports distinguish direct access state from independently indexed LinkedIn discovery.

## Workspace and UI

Storage generation 5 starts from empty SQLite, refusing historical generations and
unversioned established tables. No old profile, CV, feedback, cache or source stop is
imported. The developer explicitly authorized removal: after guarded idle shutdown,
only this checkout's identified `.private` data, backups and historical verification
copies were removed. Private runtime binaries, install identity, Git/code worktrees,
provider-owned credentials and the independent second computer were preserved.
Root `.private/state.sqlite3` now has schema 5 and empty onboarding. Synthetic V5
verification databases are separate and are never imported into the user workspace.
Later V5 launches preserve generation-5 data. V1–V4 upgrades fail closed, requiring a
separately authorized fresh start; there is no automatic historical restoration.

Upload PDF/DOCX, preview extraction, write one next-move text, review/edit a concise
understanding, then approve research. No Global, Apply-to-all, Scope, Required-by-me,
country-code or repeated Advanced Preferences controls. Internal provenance validation
and one targeted quote correction remain. Privacy/provider/source permission controls
are separate. Routine is manual/daily/weekly, with Run now / Remind later / Skip on
reopening; no Windows task is created and a switched-off PC cannot research.

Country tabs come from confirmed intent, including countries beyond DE/NL. Vacancy
feedback automatically belongs to its evidenced country; unknown countries remain
unclassified. Separate per-country learning and private assessment calls avoid using
another country's feedback. Application rejection is not negative preference feedback.
Save/Applied/Interview/Offer/Rejected and dated application history remain independent.

## JobSpy comparison

Reviewed [JobSpy LinkedIn implementation](https://github.com/speedyapply/JobSpy/blob/main/jobspy/linkedin/__init__.py)
and [MIT license](https://github.com/speedyapply/JobSpy/blob/main/LICENSE).
It uses the same guest search endpoint/numeric identities, deduplication and
`show-more-less-html__markup`, while details use ordinary `/jobs/view/{id}` and
BeautifulSoup. Existing integration uses the guest detail endpoint and a lightweight
parser. A failed guest endpoint is not followed with JobSpy's alternate detail route.

Fixtures exposed a maintainable improvement: exact class tokens, single-quoted
attributes and mixed-case nested DIVs. The existing parser was improved and tested;
missing descriptions still remain missing, and unrelated footer text is excluded.
JobSpy/BeautifulSoup was not installed or executed here and no JobSpy source was copied.
Its superiority on malformed HTML is not claimed. Existing attribution is retained.
